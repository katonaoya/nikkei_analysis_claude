# モデル再構築・ダブルエージェント開発ガイド

このディレクトリは、2名（または2エージェント）が並行してモデル開発を進める際の参照資料です。以下のルールに従い、作業衝突を避けながら効率よく進めてください。

## 1. 体制と役割

### Agent A（データ＆モデリング担当）
- データ再整備（銘柄別前処理、特徴量生成、データリーク検証）。
- モデル再学習パイプラインの実装（ウォークフォワード、キャリブレーション分離、評価指標計測）。
- モデルレジストリ更新と成果物（学習済みモデル、メトリクスレポート、キャリブレーション曲線）の作成。

### Agent B（バックテスト＆運用担当）
- `production/backtest_engine_v2.py` の拡張（複数シナリオ、スリッページ感度、可視化）。
- シャドー運用の自動化（デイリーログ、エクイティ推移、異常検知アラート）。
- Readiness Dossier（Go/No-Go 判定資料）と運用手順書の整備。

## 2. ブランチとファイル管理
- 基本方針：**同じファイルを同時に編集しない**。コンフリクトが避けられない場合は事前に相談し、担当セクションを明確化。
- 推奨ブランチ例
  - Agent A: `feature/model-refactor`
  - Agent B: `feature/backtest-shadow`
- 共有設定（YAML/JSON 等）を更新するときは、PR 説明欄で変更内容と影響範囲を必ず明記。

## 3. 成果物の配置ルール
- モデル成果物
  - `models/enhanced_close_v2/<model_id>/`
  - `reports/model_eval/<yyyymmdd>_summary.md`
- バックテスト＆シャドー運用
  - `results/backtest_v2/`（CSV, JSON）
  - `reports/backtest/<yyyymmdd>_analysis.md`
  - `logs/shadow_run/<date>.json`

## 4. 同期ポイント
1. **データ仕様レビュー**（初期）：特徴量一覧、訓練/検証期間、除外ルールを合意。
2. **モデル→バックテスト連携**（中盤）：出力フォーマット（推奨銘柄リスト、確率欄など）を決定。Agent A がダミー出力を提供し、Agent B が取り込みテストを実施。
3. **統合デモ**（終盤）：再学習済みモデルを用いたバックテスト／シャドー結果を双方で確認し、Go/No-Go 判断に向けた資料を整える。

## 5. コミュニケーション手順
- 進捗共有は毎日または隔日で短報（Slack/Issue テンプレートを想定）。
- ブロッカー発生時は相手の作業を止めないよう、早めに Issue で相談。
- PR 作成時は「何を、なぜ、どこまで確認したか」を明記し、最低1件は相互レビューを行う。

## 6. 作業ログテンプレート
各エージェントは以下の形式で `docment/ユーザー情報モデル開発/agentX_log.md` に作業ログを追記してください。

```
## 2025-10-08
- [進捗] 実施したタスク
- [課題] 次回に持ち越すこと
- [連絡] 相手への共有事項
```

## 7. 完了条件
- Agent A が再設計モデルの評価レポートとモデルアーティファクトを提出。
- Agent B がバックテスト／シャドー運用の評価レポートを提出し、Go/No-Go 判定資料を整備。
- 上記を合わせて Readiness Dossier を完成させ、最終レビューで承認が得られた時点で「完全移行可」とする。
