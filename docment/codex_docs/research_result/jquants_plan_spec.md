# J-Quants各プラン仕様まとめ（2024-10時点）

JPXが提供する「J-Quants API」は、株価・指数・信用残・財務データをHTTPS経由で提供する有償/無償サービスです。ここでは公式GitBook「プランごとに利用可能なAPIとデータ期間」および価格ページで公開されている仕様を整理し、チーム内で現在契約しているスタンダードプランとの比較がすぐできるようにしました。

## 情報ソース
- `docment/ユーザー情報/J-Quantsスタンダードプラン.md` – スタンダードプランで実際に利用しているエンドポイントと取得例。
- `docment/old/データ使用状況.md` – レート制限（100req/分）や認証フローの実装メモ。
- JPX公式GitBook: <https://jpx.gitbook.io/j-quants-ja/outline/data-spec>（プラン別データ期間/対応API）
- J-Quants料金ページ: <https://jpx-jquants.com/jquants/>（Trial/Standard/Premium/Proの価格と対象ユーザー）

## プラン詳細

### Trial（無料評価プラン）
- **想定用途**: API仕様の確認やPoC。商用や自動売買システムへの常時組み込みは利用規約で禁止。
- **データ範囲**: `/prices/daily_quotes`は約60営業日分、指数・信用系は直近年分、財務は最新決算期のみとGitBookで明示。履歴を跨ぐクエリを送っても最新ブロック以外は空レスになる。
- **サポートAPI**: 上場銘柄情報、日次株価、指数、投資部門別売買、信用残、空売り関連など限定セット。分足・先物/個別オプション・配当・財務諸表明細等はレスポンスすら返らない。
- **認証/レート**: Standard/Premiumと同じリフレッシュ→IDトークン方式。実測で約100req/分を超えると429が返るため、PoCでもスリープ必須。
- **成果物への活用**: 稼働系では使えないため、内部検証用ノートやAPIクライアント単体テストに限定する。

### Standard（現行契約プラン）
- **料金と契約**: 月額9,900円（税込）で月単位解約可。年払いも同額換算で提供。チームはこのプランを契約済み。
- **カバレッジ**: 日次OHLC・信用残・空売り・指数・投資部門別・TOPIX・日経225指数オプション等で過去10年アクセス可。取引カレンダーは「10年前〜翌年末」、決算発表予定は直近のみ。
- **エンドポイント**: `docment/ユーザー情報/J-Quantsスタンダードプラン.md` に列挙済みの13カテゴリ（/listed/info, /prices/daily_quotes, /fins/statements, /markets/trades_spec など）。`/option/index_option`のような指数オプションまでは利用可。
- **使えないAPI**: `/v1/prices/prices_am`,`/v1/prices/prices_pm`,`/v1/prices/prices_by_minutes`,`/v1/derivatives/futures`,`/v1/derivatives/options`,`/v1/markets/breakdown`,`/v1/fins/dividend`,`/v1/fins/fs_details` 等はPremium限定。
- **レート制限**: `docment/old/データ使用状況.md`にある通り100リクエスト/分。実装では2秒スロットリング＋ページネーション処理で確実に回避している。
- **社内運用Tips**:
  - 5桁コード（例: 86970）に変換しないと一部APIで400が返る。`utils/fetch_stocks_config.py`の`JQuantsFetcher`で既に吸収。
  - 取得結果は`data/`と`production_data/`にパケット化し、モデル側は`systems/`で参照する運用。

### Premium（分足・詳細財務まで必要な場合）
- **料金と契約**: 月額49,500円（税込）。最低利用期間1か月。法人名義の登録と用途確認が必要。
- **追加データ1: 高頻度株価**  
  - `/v1/prices/prices_am` `/prices_pm`: 前場/後場ごとのOHLCと出来高。  
  - `/v1/prices/prices_by_minutes`: 1分足（東証立会/PTS含む一部銘柄は5分足補完）。GitBook上は「最大3年、保証1年」。
- **追加データ2: デリバティブ・出来高内訳**  
  - `/v1/derivatives/futures`, `/v1/derivatives/options`: 個別限月まで取得可能。  
  - `/v1/markets/breakdown`: 売買内訳（自社/委託別等）。
- **追加データ3: 財務詳細・配当**  
  - `/v1/fins/dividend`: 配当金額、権利確定日、支払日。  
  - `/v1/fins/fs_details`: 有報レベルのBS/PL/CF明細。
- **制約**: データ量が膨大なため、JPXに利用予定を提出し追加のレート枠（300〜600req/分）を申請するのが一般的。レスポンスは15分遅延でリアルタイムではない点に注意。
- **向いているケース**: 分足でのシグナル抽出、前後場別VWAP、配当落ち調整アルゴ、先物/OPを含む裁定など。

### J-Quants Pro（リアルタイム配信サービス）
- **位置づけ**: APIプランとは別ライン。証券会社やヘッジファンド向けに提供されるリアルタイム（サブ秒）ストリーミング。
- **内容**: 東証現物/先物/OPのリアルタイム板、歩み値、出来高、指数、速報イベント。専用SDKと回線で提供され、ディレイ無し。
- **契約条件**: 料金は非公開の個別見積。接続審査と利用報告が義務。オンプレ環境やクラウド上での厳格な管理が求められる。
- **利用判断**: 当チームのアルゴは日次〜分足ベースのため即導入は不要。ただし分足モデルやリアルタイムシグナルを検討する際の候補として整理。

## 運用観点メモ
- **認証フロー統一**: どのプランでも `POST /v1/token/auth_user` → `POST /v1/token/auth_refresh` の2段階。IDトークンは24時間で失効するため、バッチ前に必ず更新。
- **API呼び出し作法**: `from/to`で範囲指定し、レスに`pagination_key`が含まれていたらループで追いかける。長期ループは`time.sleep(2)`で間引く。
- **データ保存**: 試験データは`data/`、本番データは`production_data/`に保存して`systems/`配下のモデルが読む。スタンダード以上であればOHLC/信用/指数が10年そろうため、再取得コストは低い。
- **プラン見直しの目安**:
  1. 分足や前後場別の特徴量が必要 → Premiumを検討。
  2. リアルタイム板情報が必要 → J-Quants Proよりもkabuステーション等の方が費用対効果が高いケースが多い。
  3. 過去データの追加だけならStandardで十分。既に`docment/ユーザー情報/J-Quantsスタンダードプラン.md`に網羅されている13 APIを順繰りに叩けばOK。
